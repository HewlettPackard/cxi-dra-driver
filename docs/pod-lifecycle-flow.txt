cxi-dra-driver — Pod Lifecycle Flow
=====================================

This document describes the mechanisms used during pod scheduling and
de-scheduling, annotated with the driver component responsible for each step.
It also covers the orphan-service reaper that closes the gap between
event-driven teardown and live hardware state.

Capacity is accounted with DRA consumable capacity: every CXI device publishes
txqs, tgqs, eqs, cts, ptes, acs, les and tles as capacity (valued at the usable
ceiling = hardware total − blessed system services), and the scheduler charges
each claim's capacity.requests against it. The ResourceSlice is static —
published once at driver startup — and the scheduler tracks consumption in each
claim's status.allocation.devices.results[].consumedCapacity.


══════════════════════════════════════════════════════════════════════════════════════
  SCHEDULE PATH
══════════════════════════════════════════════════════════════════════════════════════

  User / controller
      │  kubectl apply replicaset / pod
      ▼
  API Server ──► MutatingAdmissionPolicy (legacy claims only) ─────────────────────┐
  (ResourceClaim                          intercepts ResourceClaim CREATE           │
   CREATE)                                if config[0] is CXI opaque config, for    │
                                          each request it names (all DeviceClass    │
                                          requests if none) lacking capacity:       │
                                            adds exactly.capacity.requests          │
                                            (txqs…acs as-is, le_pools×1024 → les,   │
                                             tle_pools×512 → tles)                  │
                                          claims already using capacity.requests    │
                                          pass through untouched                    │
      │ claim carries capacity.requests   ◄────────────────────────────────────────┘
      ▼
  DRA Scheduler
      │  reads ResourceSlice: per-device capacity + requestPolicy (static)
      │  for each candidate device and each capacity:
      │    request rounded up by requestPolicy (les → ×1024, tles → ×512;
      │      unrequested capacities consume the policy default)
      │    Σ consumedCapacity of claims already on the device + request ≤ value?
      │  applies selectors / matchAttribute constraints (e.g. numaNode with GPU)
      │  allocates: CXI device → claim.status.allocation, recording
      │    consumedCapacity and a per-allocation shareID
      │  ▲ accounting is atomic inside the scheduler, so a batch of claims
      │    cannot over-concentrate on one NIC
      │  ┌──────────────────────────────────────────────────────────────┐
      │  │  WAITS: BindingConditions ["Ready"] = True before binding    │
      │  └──────────────────────────────────────────────────────────────┘
      │ (allocation written to claim.status)
      ▼
  ClaimBinder  ◄── watch event (ResourceClaim MODIFIED, allocation set)
      │  safety net for consumption the scheduler cannot see: services created
      │  outside Kubernetes, claims allocated before devices published capacity
      │  (their consumedCapacity is empty, so the scheduler counts them as 0)
      │
      │  requested = consumedCapacity (opaque config for pre-upgrade claims)
      │  ReadAvailableCapacity(device)           ← real hardware counters
      │  pendingSum = Σ resources in pending map for this device
      │
      ├─ hwAvail − pendingSum ≥ requested ─────────────────────── READY=TRUE
      │       │
      │       └─► pending map[(claimUID,dev)] = {device, resources}
      │             prevents double-grant while service not yet created.
      │             Same-namespace claims may co-locate on one device —
      │             SHS14's duplicate-VNI constraint has been lifted.
      │
      ├─ fits hardware but pendingSum blocks ───────────────────── READY=FALSE
      │       │
      │       └─► falseClaims map
      │              ▲            ▲
      │              │            └── 2 s ticker (safety-net poll)
      │              └─────────────── TriggerRetry  (primary, event-driven)
      │                               fired by NRI after service create/delete
      │
      └─ hwAvail < requested (device truly full) ──────────── UNSCHEDULABLE
              │                                                (DeviceAtCapacity)
              └─► Scheduler sees Unschedulable in BindingFailureConditions
                  deallocates the CXI claim and retries
                  ▲ single claim (CXI only); namespace VNI lives in annotation,
                  │ not in the claim
                  ▲ the scheduler's accounting does not include the out-of-band
                    consumption that filled the device, so the retry may pick the
                    same device until that consumption goes away. With only
                    Kubernetes-managed services on the NIC this branch never fires.
      │
      │ Ready=True set
      ▼
  Scheduler binds pod to node
      │
      ▼
  Kubelet: PrepareResourceClaims
      │  resolves requested resources per device:
      │    consumedCapacity (authoritative; what the scheduler charged)
      │    ├─ legacy opaque config present and asks for more → reject
      │    │    (claim was never converted; would be under-provisioned)
      │    └─ no consumedCapacity (pre-upgrade allocation) → opaque config
      │  static ceiling check: requested ≤ (hardware_total − svc reserved)
      │    └─ rejects here if request can never fit regardless of load
      │  reads VNI from namespace annotation cxi.slingshot.hpe.com/vni
      │    (10-retry: allocator may not have annotated yet)
      │  stores PodAllocation in AllocationStore
      │    (device path, HSN interface, VNI, requested resources)
      │  writes CNI hint file <--cni-hints-dir>/<podUID>.json (atomic)
      │  returns CDI device IDs to kubelet
      │
      ▼
  containerd + CDI
      │  injects /dev/cxiN into container filesystem
      │  programs cgroup BPF allowance for major:minor
      │  ▲ must happen before cgroup policy is locked in;
      │    NRI alone fires too late for cgroup — CDI handles this
      ▼
  CNI ADD: slingshot-cni  (separate host process, exec'd by containerd/Multus)
      │  reads hint file for K8S_POD_UID (bounded retry)
      │  per device:
      │    L2 IPVLAN sub-interface on host <hsn_iface> → moved into pod netns
      │      renamed <ifname> or <hsn_iface> (fallback <name>_inet if taken), set up
      │    DelegateAdd(ipam.type=whereabouts, CNI_IFNAME=<in-pod name>)
      │      ▲ per-device CNI_IFNAME: Whereabouts keys on (containerID, ifname)
      │    apply returned address + routes
      │  any failure → unwind every interface/reservation made this invocation
      │  ▲ L3 only — complementary to the NRI sysfs injection below, which is
      │    what stock libfabric's HSN discovery depends on
      ▼
  NRI: RunPodSandbox
      │  netns inode via /proc/<sandbox-pid>/ns/net + fstat
      │  ▲ os.Stat on bind-mount path gives wrong (tmpfs) inode — not nsfs
      │
      │  per-device mutex.Lock()  ◄── serialises concurrent pods on same device
      │
      │  ══ LIVE FIT-CHECK ══════════════════════════════════════════════════
      │  ReadAvailableCapacity(device)
      │  requested.Fits(hwAvail)?
      │    no → unlock, return error  (safety net for TOCTOU window
      │                                between Ready=True and service create)
      │  ═════════════════════════════════════════════════════════════════════
      │
      │  cxil_alloc_svc (VNI in descriptor) → cxil_svc_enable(off) →
      │    cxil_svc_set_netns → cxil_svc_enable(on)
      │     ▲ SHS14 now permits multiple services sharing a VNI on one device,
      │       so co-tenant pods from the same namespace allocate cleanly.
      │       SHS14 requires the service to be disabled before
      │       cxil_svc_set_netns and re-enabled after.
      │
      │  per-device mutex.Unlock()
      │
      │  buildNetSysfs: host /sys/class/net/<hsn> → per-pod synthetic tree
      │    <root>/<podUID>/net = real-iface symlinks (setns+private mountns+
      │      fresh sysfs mount in pod netns) + hsnN/{operstate=up, carrier=1,
      │      speed, device→…/<BDF>}
      │    ▲ stock (unpatched) libfabric reads HSN link metadata from here;
      │      a hard error rolls the services back so a pod where libfabric
      │      cannot bootstrap never starts. Skipped in mock mode.
      │
      │  RemovePending(claimUID) ─── pending map entry released
      │     ▲ the service is now live on the device, so its resources are
      │       already reflected in the live hardware counters; the pending
      │       reservation is no longer needed
      │  TriggerRetry ──────────────────────── re-evaluates falseClaims
      │
      ▼
  NRI: CreateContainer
      │  injects SLINGSHOT_DEVICES=cxi0, SLINGSHOT_VNIS=<n>, SLINGSHOT_SVC_IDS=<n> env vars
      │  mounts a fresh tmpfs at /dev/shm (per container; never the host's /dev/shm)
      │  bind-mounts <root>/<podUID>/net OVER /sys/class/net (ro)
      │    ▲ only /sys/class/net is overmounted, so the pod keeps its own NICs:
      │      replicated symlinks resolve through the untouched /sys/devices.
      │      libfabric's link gate (cxip_if.c) has NO env bypass, hence operstate=up.
      │      its AMA gate needs CXIP_SKIP_AMA_CHECK=1, supplied via the CDI env
      │      config (NOT injected here).
      │
      ▼
  Pod running ✓
      /dev/cxiN accessible, SLINGSHOT_DEVICES/VNIS/SVC_IDS set, netns-scoped VNI bound,
      stock libfabric discovers the HSN via the injected /sys/class/net,
      <ifname> (or default <hsn_iface>) IPVLAN netdev carries a Whereabouts address
      for IP over the HSN


══════════════════════════════════════════════════════════════════════════════════════
  DE-SCHEDULE PATH (three cleanup paths, all idempotent)
══════════════════════════════════════════════════════════════════════════════════════

Scheduler-side capacity is released by the scheduler itself: once a claim is
deallocated or deleted its consumedCapacity no longer counts against the
device. The driver's paths below only clean up its own state — two
event-driven paths release the in-flight pending grant, and a third
hardware-aware path reaps CXI services whose owning pod is gone. All are
idempotent.


┌─── Path A: NRI StopPodSandbox (normal pod termination) ─────────────────────┐
                                                                              │
  Pod deleted / completed                                                     │
      │                                                                       │
      ▼                                                                       │
  NRI: StopPodSandbox                                                         │
      │  per-device mutex.Lock()                                              │
      │  cxil_destroy_svc            ← hardware service torn down             │
      │  AllocationStore.Delete(podUID)                                       │
      │  os.RemoveAll(<root>/<podUID>) ← per-pod synthetic /sys/class/net tree│
      │  per-device mutex.Unlock()                                            │
      │                                                                       │
      │  TriggerRetry ───────────────── re-evaluates falseClaims immediately  │
      │                                                                       │
      ▼                                                                       │
  Kubelet: UnprepareResourceClaims                                            │
      │  AllocationStore cleanup only                                         │
      │  best-effort removal of the CNI hint file (never blocks release)      │
      │  (does NOT destroy the kernel service — that is owned by NRI above    │
      │   and the reaper below; racing the service in the rare NRI-failed     │
      │   case would churn resources on the next claim)                       │
      │                                                                       │
      ▼                                                                       │
  ResourceClaim garbage-collected  (ephemeral template claim)                 │
      ▲ its consumedCapacity stops counting against the device                │
                                                                              │
  In parallel, containerd runs CNI DEL: slingshot-cni                         │
      │  per device: Whereabouts DelegateDel under the in-pod name ADD used, │
      │    then delete the IPVLAN link                                        │
      │  idempotent: missing hint file / netns / link = success; only IPVLAN  │
      │    links are ever deleted; all devices attempted, errors joined       │
      │  no ordering vs. the hint-file removal above — if the hint is already │
      │    gone, DEL logs and succeeds; Whereabouts ip-reconciler GCs leftovers│
                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘


┌─── Path B: ClaimBinder watch (scheduler-side cleanup) ──────────────────────┐
                                                                              │
  Scheduler clears claim.status.allocation:                                   │
    - PostFilter de-allocates after PreBind failure                           │
    - Unschedulable=True signal                                               │
    - Manual edit / claim deletion                                            │
      │                                                                       │
      ▼                                                                       │
  ClaimBinder.evaluateClaim(claim) sees Allocation = nil                      │
      │  (or onClaimDeleted fires on watch.Deleted event)                     │
      │                                                                       │
      │  RemovePending(claimUID)                                              │
      │    ▲ clears every pending entry for the claim; no-op if the claim     │
      │      never held a grant or NRI already released it                    │
                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘


┌─── Path C: Orphan-service reaper (drift backstop, hardware-aware) ──────────┐
                                                                              │
  reaper ticker (driver.Run loop, --resource-refresh-interval)                │
      │                                                                       │
      ▼                                                                       │
  reapOrphanServices                                                          │
      │  skip if mockDevices != nil                                           │
      │                                                                       │
      │  LiveSvcIDs() → svc_ids the NRI plugin still owns for live pods       │
      │  for each device:                                                     │
      │    cxi.ReadActiveServices(dev) → [{svc_id, vni, is_system_svc}, …]    │
      │    for each service, PRESERVE if ANY of:                              │
      │      - svc_id is blessed (--system-svc-ids)                           │
      │      - is_system_svc bit set (Ethernet/default services)              │
      │      - owned by a live pod (LiveSvcIDs)                               │
      │      - the netns the kernel recorded is still live on the node        │
      │      - that netns cannot be determined (read error / 0)               │
      │    otherwise it is a candidate orphan                                 │
      │                                                                       │
      │  a candidate is deleted only after it has looked orphaned for N        │
      │  consecutive cycles (grace period avoids racing a just-created svc)   │
      │    → cxil_destroy_svc(dev, svcID)                                     │
                                                                              │
  Drift sources this path covers:                                             │
    - Driver restart leaving services from a prior process                    │
    - Force-deleted pods whose NRI StopPodSandbox never fired                 │
    - containerd StopPodSandbox short-circuits (len(allocs)==0, etc.)         │
    - Out-of-band service creation                                            │
                                                                              │
└─────────────────────────────────────────────────────────────────────────────┘


══════════════════════════════════════════════════════════════════════════════════════
  COMPONENT SUMMARY
══════════════════════════════════════════════════════════════════════════════════════

  Component               Role
  ─────────────────────   ──────────────────────────────────────────────────────────
  MutatingAdmissionPolicy Converts legacy opaque resource config on requests[0]
                            into exactly.capacity.requests at claim CREATE
  ResourceSlice           Static, published once at startup: per-device
                            consumable capacity (txqs…tles, valued at the usable
                            ceiling, LE/TLE pool steps) + topology attributes
                            (type, hsn_iface, numaNode, pciBusID)
  DRA Scheduler           Primary capacity gate: charges each claim's
                            capacity.requests against device capacity, records
                            consumedCapacity + shareID; waits on
                            BindingConditions; retries on Unschedulable
  ClaimBinder             Safety net against live hardware for consumption the
                            scheduler cannot see; 3-way decision:
                            Ready=True / Ready=False /
                            Unschedulable: DeviceAtCapacity
  Pending map             map[(claimUID,dev)]pendingEntry{dev, resources}.
                            Bridges gap between Ready=True grant and service
                            creation; prevents double-grant on same device
  Orphan-service Reaper   Ticker-driven backstop that destroys CXI services whose
                            owning pod is gone, via cxi.ReadActiveServices +
                            LiveSvcIDs + per-service netns liveness. Recovers from
                            driver restart, force-deleted pods, NRI short-circuits
  TriggerRetry            Event-driven re-evaluation of Ready=False queue
                            (primary path)
  reaper ticker           Drives reapOrphanServices (--resource-refresh-interval)
  PrepareResourceClaims   Resolves resources from consumedCapacity (opaque config
                            fallback); static ceiling check; VNI lookup from
                            namespace annotation; AllocationStore write;
                            atomic CNI hint-file write (handoff to slingshot-cni)
  UnprepareResourceClaims AllocationStore cleanup + best-effort CNI hint-file
                            removal — service teardown is owned by NRI (Path A)
                            + the reaper (Path C)
  CDI                     /dev/cxiN injection + cgroup BPF allowance
                            (pre-cgroup-lock)
  CNI ADD / DEL           slingshot-cni (cmd/slingshot-cni + internal/cni),
                            a separate host process exec'd by containerd/
                            Multus. ADD: per claimed device, L2 IPVLAN on the
                            host hsn_iface moved into the pod netns as
                            <ifname> (default hsn_iface, fallback <name>_inet) + Whereabouts
                            IPAM address; unwinds on partial failure. DEL:
                            release + delete, idempotent (missing hint/netns/
                            link = success; only IPVLAN links deleted). Owns
                            L3 only — complementary to HSN sysfs injection.
  NRI RunPodSandbox       Live fit-check under per-device mutex; hardware
                            service create; per-pod synthetic /sys/class/net
                            build (HSN sysfs injection); RemovePending
  NRI CreateContainer     SLINGSHOT_DEVICES/VNIS/SVC_IDS env var injection;
                            fresh per-container tmpfs at /dev/shm;
                            bind-mounts the synthetic /sys/class/net over the
                            container's so stock libfabric discovers the HSN
                            device (AMA bypass supplied via the CDI env config)
  NRI StopPodSandbox      Hardware service destroy; per-pod synthetic sysfs
                            tree removal; unblocks waiting pods via TriggerRetry
  HSN sysfs injection     internal/netsysfs: builds <root>/<podUID>/net with a
                            symlink per real pod NIC (read by entering the pod
                            netns and mounting a fresh sysfs) plus an hsnN dir
                            (operstate=up, carrier, speed, device→<BDF>). Lets
                            UNPATCHED libfabric bootstrap the CXI device in-pod;
                            RDMA itself is kernel-bypass and needs no netdev.

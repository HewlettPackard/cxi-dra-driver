# Changelog

All notable changes to `cxi-dra-driver` will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) via its `v*` release tags.

## [Unreleased]

### Added
- `make lint` runs golangci-lint at a version pinned in the `Makefile`, against the Linux build from any host, and `.github/workflows/build.yaml` gains a lint step that uses it.
- `.github/workflows/pr-checks.yaml`: internal pre-merge gate that runs `go vet`, `make lint` and `go test ./...` on every pull request to `main`, on an ephemeral VM through the `create-runner` pattern.
- CI for the public GitHub repository: `.github/workflows/build.yaml` runs on GitHub-hosted runners and publishes the multi-arch image to `ghcr.io/hewlettpackard/cxi-dra-driver` on every merge to `main`, tagged with the short commit SHA and `main`. `.github/workflows/release-chart.yaml` runs after a successful build on `main`, and when the chart version is unreleased it promotes that commit's image to the official `appVersion` tag (immutable; e.g. `0.1.0`), pushes the chart to `oci://ghcr.io/hewlettpackard/charts`, and creates the GitHub release. Both use `GITHUB_TOKEN` only. The chart's `image.tag` now defaults to `appVersion` (`pullPolicy: IfNotPresent`), and the raw manifests and `Makefile` point at the new image.
- Mock VF topology for kind and CI: `--mock-vfs=<parents>x<vfs-per-parent>` (implies `--vf-only`) generates one mock PF with parent services (hardware-measured budget, one Ethernet child per VF, disjoint VNI sets in range and list form) and their VFs, and installs the topology the parent reads and the mock service manager use. `deploy/kind/setup.sh` takes `MOCK_VFS` (the DaemonSet template now has a `__MOCK_ARG__` placeholder) and `deploy/kind/test-vf.sh` checks VF placement, `vfs` and shared-budget exhaustion, first-allocation parent selection by namespace VNI with no `Unschedulable` bounces, and a namespace no parent covers staying Pending. `--mock-devices` is unchanged.
- **SR-IOV VF mode** (`--vf-only`, Helm `driver.vfOnly`, commented option in `deploy/kubernetes/daemonset.yaml`) is now documented and configurable end to end. On nodes whose Cassini NIC exposes VFs, the driver publishes each administrator-provisioned **parent CXI service** as one shareable device (`<pf>-svc<id>`) with the parent's budget (less one Ethernet system child per VF; LEs/TLEs 0) plus a `vfs` capacity, and picks a free VF per claim at Prepare under a per-parent lock; VFs are not published. The new README § SR-IOV VF Mode covers the parent-as-device model, LE pressure and parent sizing, provisioning order for every PF, parent file guidance (resource limits are mandatory), verification (`fi_info -p cxi` lists the VFs), the SHS requirement (15.0.0 is not supported), claims (LE/TLE must be 0), the `cxi-dra-vni-selector` admission policy (required for multi-parent nodes; without it a VNI mismatch loops through `Unschedulable` bounces on the same parent) and Known Limitations. `CONTEXT.md`, `ARCHITECTURE.md` (new §3.11), the package READMEs, the domain-patterns instructions, `copilot-instructions.md` and the glossary skill gain the VF-mode model and anti-patterns. The default (PF mode) is unchanged. Kubernetes KEP-5941 (DRA Shared Consumable Capacity; targeted at alpha in 1.38) is the planned follow-up model, publishing VFs as devices that draw from a shared parent counter.
- VF CNI hints now carry `ifname: cxiN` using the existing schema version 1 while retaining the VF host netdev as `hsn_iface`. The NRI synthetic sysfs exposes the same `cxiN` name with PCI metadata read from that host link. PF hints and sysfs naming remain unchanged.
- VF-mode `ResourceSlice` attributes and VNI admission selector. A parent device now publishes `function_type: parent`, `pf_name`, `pf_netdev` (omitted when unresolvable), `parent_svc_id`, its VNI set as `vni_min`/`vni_max` (a range, or a contiguous list) or the delimiter-wrapped `vni_set` (`",40,42,"`; `","` when the set could not be read, so no namespace matches), the PF's own `numaNode`/`pciBusID`, and a `vfs` capacity (default 1, valid range 1–1) that keeps VFs exclusive; it publishes no `hsn_iface`. PF devices gain `function_type: pf` and are otherwise unchanged. New `cxi-dra-vni-selector` `MutatingAdmissionPolicy` + binding (raw manifests and Helm, with `admissionPolicy.enabled`/`excludedNamespaces`) appends a VNI-coverage CEL selector to every CXI request in a namespace with a valid `cxi.slingshot.hpe.com/vni` annotation, keeping a user-supplied selector and always matching PF devices, so the scheduler never allocates a parent whose VNI set misses the namespace VNI. `cxi.Device`/`cxi.Parent` carry the PF's PCI address, NUMA node and netdev, read from sysfs. `deploy/kind/test-admission-policy.sh` covers `le_pools: 0` and the selector cases. LE/TLE must be 0 in VF mode (documented on the example claims).
- VF-mode driver integration: Prepare and the ClaimBinder reject a namespace VNI outside the parent's VNI set (Prepare fails the claim; the ClaimBinder sets `Unschedulable=True` `VNINotInParentSet` and logs a warning, since the admission VNI selector should have kept the scheduler off that parent). Claims on a parent with non-zero `les`/`tles` consumed capacity or `le_pools`/`tle_pools` opaque config are rejected because children inherit LE/TLE pools from the parent. At startup each parent logs its budget, Ethernet-child reservation, published ceiling and VNI set, and warns when the VNI set does not cover `--vni-range-start`..`--vni-range-end` or fewer than one LE pool (1024) remains. PF mode is unchanged.
- Orphan-service reaper VF safety: in `--vf-only` mode `--system-svc-ids` no longer applies to the reaper (svc_ids are per-VF), the VF Ethernet child is preserved by its system bit, and a non-system VF child that no live pod or hint file accounts for is logged as a warning (first sight, then every 60 cycles) because it reduces the parent's shared budget. Grace cycles and netns checks are unchanged; new `reaper_test.go`.
- VF child service creation uses explicit parent context, inherits the parent's LE maximum with zero LE/TLE reservations, and retains pod-netns binding and single-VNI restriction. The mock enforces shared-parent budgets and VNI coverage, including system reservations and deletion recovery. Existing PF calls retain their behavior.

- VF mode publishes parents and selects VFs at Prepare. With `--vf-only` the `ResourceSlice` holds one device per parent service, `<pf>-svc<id>`, whose ceiling is the parent budget minus one Ethernet-child reservation per VF, with LEs/TLEs 0. Prepare gives each allocation result the lowest free VF of its parent under a per-parent lock: results of one claim get distinct VFs, a re-Prepare keeps the claim's VFs, and a parent with no free VF fails with the holder of every VF. The VF backs the pod's CDI device, NRI service and CNI hint, and is shown as `vf` in the claim's device status. The ClaimBinder and NRI fit check use the parent's live remaining budget, and pending grants are per (device, ShareID). On startup the driver restores VF occupancy from CNI hint files and live claims (so Unprepare after a restart releases them), and marks VFs with a pod child but no hint busy until the reaper removes the child. PF mode is unchanged.
- VF discovery resolves parent service assignments from PF sysfs and skips VFs with invalid/unassigned IDs or parents without resource limits. `Parent` / `Parents()` group assigned VFs by (PF, service ID) in stable order; PFs without VFs are logged. Covered by fake-sysfs tests and an assigned-VF hardware smoke test.
- `--vf-only` selects SR-IOV VF mode: discovery publishes VFs only and skips PFs before any libcxi read, so a PF is never opened; the default still publishes PFs only. PFs and VFs are never mixed. `Device` gains `FunctionType`, `PFName` and `VFIndex` (and the `ParentSvcID`/`PodIfName` placeholders), `cxi.Discover` takes `DiscoverOptions`, devices are returned in index order, every skipped device is logged with the reason, and `--vf-only` with no usable VF logs an error and publishes an empty slice. With `--vf-only`, `--system-svc-ids` is ignored with a warning: its PF svc_ids would match pod children in a VF's own svc_id space and block their deletion. Discovery is unit-tested against a fake sysfs tree. Groundwork for SR-IOV: VFs are found from sysfs alone and published with zero capacity, so any claim that requests resources is refused on a VF until parent budgets land. 
- `internal/cxi` VF-mode read path for SR-IOV: `ReadParentBudget`, `ReadParentRemaining` and `ReadVFSystemReservation` read a parent service's budget and VNI set from the PF and sum the reserved resources of the services on its VFs; new `VNISet` type (range or list). Parents without resource limits are rejected with `ErrParentUnlimited`. The PF-mode reads are unchanged, and the non-cxi build answers from an in-memory mock topology.
- `slingshot-cni` accepts an optional `ifname` hint to separate the pod-side IPVLAN name from its host parent link, retaining legacy PF names when absent. Version-1 hint entries support explicit schema checks; unsupported newer versions are logged and rejected. Base names must leave room for `_inet` within Linux's 15-byte limit.
- `slingshot-cni` is now bundled into the driver image and can be installed onto nodes by the driver itself: new `--cni-install-dir` / `--cni-src` flags (default off), Helm `cni.install` / `cni.binDir`, plus an optional `NetworkAttachmentDefinition` render (`cni.nad.*`). Entirely opt-in — default renders are unchanged and `hostNetwork`/future SR-IOV remain first-class. `make build-cni` honours `GOARCH`; the image build compiles `slingshot-cni` itself.
- `slingshot-cni` now produces a working HSN-backed pod interface end-to-end: on `ADD` it creates one L2 IPVLAN sub-interface per claimed CXI device on the paired host HSN, moves it into the pod netns as `<hsn_iface>` (falling back to `<hsn_iface>_inet`), and delegates addressing to the Whereabouts IPAM plugin per the standard CNI delegate contract; `DEL` releases the address and tears the interface down idempotently; `CHECK` verifies both. Multi-device (`count > 1`) claims are fully supported. The driver's `internal/netsysfs` injection runs alongside; VF mode gives its entry the same `cxiN` name as the pod interface while retaining the host VF's PCI metadata. New dependency: `github.com/vishvananda/netlink`. See `docs/cni/cni-plugin.md`.
- AI-readiness pass: `.github/copilot-instructions.md`, `CONTEXT.md`, `ARCHITECTURE.md`, `AGENTS.md`, `.github/instructions/*` (including `domain-patterns.instructions.md`), `.github/agents/*`, `.github/prompts/*`, `.github/skills/cxi-dra-glossary/`.
- Repository hygiene: `SECURITY.md`, `CONTRIBUTING.md`, `.github/pull_request_template.md`, `.github/ISSUE_TEMPLATE/bug_report.md`, `.github/dependabot.yml`, `.editorconfig`.
- CI: `go test ./...` step in `.github/workflows/build.yaml` (previously `go vet` only).
- `internal/cxi/README.md` and `internal/driver/README.md` package maps.
- Consumable-capacity scheduling: devices publish `txqs`, `tgqs`, `eqs`, `cts`, `ptes`, `acs`, `les` and `tles` as DRA consumable capacity (`allowMultipleAllocations`, at the usable ceiling; LE/TLE in whole pools) in a static `ResourceSlice` published once at startup, and the scheduler accounts for allocations via `consumedCapacity` (`internal/driver/capacity.go`). Requires Kubernetes 1.36+ (`DRAConsumableCapacity` is beta and on by default; enable it plus `DRADeviceBindingConditions` on 1.34/1.35).
- Standard device attributes `resource.kubernetes.io/numaNode` (omitted when unknown) and `resource.kubernetes.io/pciBusID` on every device.
- `.github/workflows/release-chart.yaml`: lints/templates the Helm chart, publishes it as an OCI artifact on ghcr.io and creates a release. (The `<version>-pr.<n>` prerelease chart and `pr-<n>` image were dropped with the move to the public repository.)

### Changed
- The Helm chart `version` and its `appVersion` (the official driver image tag) are both `0.1.0`, and the raw manifests in `deploy/kubernetes/` reference `ghcr.io/hewlettpackard/cxi-dra-driver:0.1.0`.
- `.github/workflows/build.yaml` and `release-chart.yaml` run on the public repository only; on the internal mirror their jobs are skipped instead of queuing for a hosted runner that does not exist there. The internal-only workflows (`pr-checks.yaml`, `sync-public.yaml`) must be disabled on the public repository, where they otherwise fail at startup (see `ARCHITECTURE.md` § CI/CD pipeline).
- `Dockerfile` is now a self-contained multi-stage, multi-arch (amd64/arm64) build: it builds libcxi from pinned SHS sources, the driver, `cxi-cdi-hook` and `slingshot-cni`, bundles an ldconfig runtime, and uses a Debian bookworm-slim runtime instead of `FROM scratch`. Nothing needs staging in `bin/`. `Dockerfile.mock` is the no-hardware image used by `make image-mock`, `make kind-load` and `deploy/kind/setup.sh`.
- `.github/workflows/build.yaml` runs `go vet` and `go test ./...`, builds each architecture natively (no QEMU), and merges the digests into one multi-arch manifest on ghcr.io.
- The `MutatingAdmissionPolicy` now converts legacy opaque resource config into `exactly.capacity.requests` instead of injecting `avail_*` CEL selectors.
- `ClaimBinder` is now a three-way live-hardware safety net (`Ready=True`, `Ready=False`, `Unschedulable` `DeviceAtCapacity`); multiple claims from one namespace may share a device, since SHS 14.0.1 lifted the one-VNI-per-device constraint. The orphan-service reaper, running every `--resource-refresh-interval`, is the remaining backstop.
- The shared `env` CDI spec (kdreg2/gdrdrv/xpmem device nodes, `/dev/shm`) is now always attached to every CXI device; with `--enable-cdi-env`, the host libraries from `--env-config` are bind-mounted at `/host/env/<basename>` along with the configured env vars. The `ldcache` object in the env config has only `enabled`; hook and ldconfig locations are driver flags (`--cdi-hook-path`, `--cdi-ldconfig-dir`, …).
- `--cdi-ldconfig-src`, `--cdi-ldconfig-linker-src` and `--cdi-ldconfig-libc-src` now default to `/ldconfig-runtime/{ldconfig,ld.so,libc.so.6}`, the layout of the bundled ldconfig runtime. `cxi-cdi-hook` execs a statically linked ldconfig directly and otherwise runs it through the bundled `ld.so`.

### Fixed
- Intermittent 100% packet loss between pods claiming several VFs (`count: 2`) on the same Slingshot network: the IPVLAN interfaces share one L2 domain and subnet, and with the kernel default `arp_ignore=0` each answered ARP for the other's IP, so peers cached the wrong MAC. `slingshot-cni` now sets `arp_ignore=1` and `arp_announce=2` on every IPVLAN it creates, before bringing it up. Fixes #36.
- The capacity-conversion `MutatingAdmissionPolicy` (raw manifests and Helm) was order-dependent: it checked only `requests[0]` and wrote every patch to `/spec/devices/requests/0/...`, so in a mixed claim such as `[gpu, cxi]` with `config[0].requests: [cxi]` the capacity landed on the `gpu` request and the `cxi` request fell back to the defaults. It now targets the requests named in `config[0].requests` wherever they sit (every request of the driver's DeviceClass when none are named), and skips requests that already carry capacity. The same fixed `[0..31]` index lists in the `cxi-dra-vni-selector` policy were replaced with CEL `transformList`.
- Tenants shared the host `/dev/shm`: the always-attached `env` CDI spec bind-mounted it read-write into every CXI pod, so pods in different namespaces could read and overwrite each other's files, which also outlived the pods. The spec no longer mounts it; the NRI plugin's `CreateContainer` now mounts a fresh per-container `tmpfs` at `/dev/shm` instead (no size cap beyond the container's memory limit; it replaces any existing `/dev/shm` mount, including a pod-specified volume). Fixes #12.
- A pod that reserved a `ResourceClaim` already prepared on its node (one claim shared by several pods) never started: kubelet prepares a claim once per node, so only the pods in `ReservedFor` at that moment got an allocation and a CNI hint, and later pods looped on `FailedCreatePodSandBox` (`hint file ... not found`). The claim watch now records the claim's prepared allocation for each pod that joins it and writes its hint. If that hint write fails, the pod is not marked recorded and the claim is retried every 2 seconds until the write succeeds.
- HSN pairing (`internal/cxi.PairDevice`) now matches a CXI device to the netdev whose resolved `device` symlink equals the device's PCI function path, instead of requiring an `hsn*` name under the same PCIe root complex. SR-IOV VF netdevs (e.g. `enp197s0f1`) are now paired, `.1` vs `.10` functions are no longer confused, and `Discover` logs a warning when a device has no paired netdev (the CNI rejects an empty `hsn_iface`). The net class directory can be overridden with `SYS_NET_PATH` (default `/sys/class/net`), mainly for tests.
- Device discovery published SR-IOV VFs (`cxi4`+ on a node with VFs enabled) as full NICs with PF capacity, so claims that the VF's parent service could never satisfy were allocated and their pods looped on `FailedCreatePodSandBox`, and a VF child whose svc_id matched `--system-svc-ids` was treated as blessed. `Discover()` now skips any `cxi*` device with `device/physfn` in the default (PF) mode.
- The raw `deploy/kubernetes/clusterrole.yaml` Lease role named `cxi-vni-allocator-leader`, but the driver's Lease is `<driverName>-vni-allocator-leader`; it now names `cxi.slingshot.hpe.com-vni-allocator-leader` so the kubectl install path can run the VNI allocator. `deploy/kind/test-vni.sh` follows.
- Documentation drift after merging the consumable-capacity work: README flag table and chart defaults, `ARCHITECTURE.md` initialization order and package indexes, `internal/driver/README.md`, `CONTRIBUTING.md`/`SECURITY.md`/PR template claims about CI-enforced linting and files that do not exist.

### Removed
- Per-device `avail_*`/`capacity_*` and `active_namespaces` `ResourceSlice` attributes, per-namespace device occupancy tracking, the occupancy reconciler, periodic `ResourceSlice` republishing (`TriggerRepublish`), and the `NamespaceDeviceOccupied` unschedulable reason, all superseded by consumable capacity.
- The `nccl` and `aws-ofi-nccl` CDI profiles (now injected by k8s-modules); their spec files are deleted on startup. NVIDIA GPU co-location (`gpu.go`) is gone as well, replaced by the standard `numaNode`/`pciBusID` attributes.
- `Dockerfile.ci` (the production `Dockerfile` is now the CI image too).
- `docs/superpowers/` (implementation plans and design specs for CDI env integration and namespace VNI allocation) — both features are fully implemented and merged (`internal/cdi/env.go`, `internal/driver/vniallocator.go`); the directory was stale, agentic-framework-specific TDD scaffolding no longer relevant once the work landed.
